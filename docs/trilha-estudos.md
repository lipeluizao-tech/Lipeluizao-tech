# Trilha de estudo com entregas

Escolha uma etapa por vez. Cada etapa termina com evidência útil para o portfólio; o tempo depende da disponibilidade e experiência.

| Etapa | Estudo | Entrega | Critério para avançar |
| --- | --- | --- | --- |
| Linux e Git | Terminal, permissões, commits e branches | Ambiente e primeiro projeto documentados | Reproduzir execução e recuperar alteração com Git |
| Python e testes | Funções, arquivos, erros e estruturas de dados | Organizador com simulação | Testar colisões, caminhos inválidos e comportamento esperado |
| Web | HTML, CSS, JavaScript e HTTP | Painel de estudos | Demonstrar funcionamento e conferir uso por teclado |
| Backend | API, banco, validação e autenticação | API de tarefas | Testar sucesso, erros e autorização entre usuários |
| Segurança | OWASP, logs e revisão de código | Relatório de laboratório local | Explicar causa, correção e teste da proteção |
| IA aplicada | Contexto e avaliação | Avaliador de assistente | Comparar resultados nas mesmas tarefas |

## Referências por etapa

- Fundamentos: freeCodeCamp e OSSU.
- Algoritmos: The Algorithms/Python; acompanhe exercícios com testes e análise de complexidade.
- Aplicações: Project Based Learning; adapte a proposta e cite a referência.
- Segurança: OWASP Cheat Sheet Series; Juice Shop ou WebGoat em laboratório local isolado.
- IA: documentação das ferramentas e o [guia de contexto](ia-contexto.md).

Os links e atividades estão no [catálogo](repositorios.md).

## Rotina de uma sessão

1. Escolha um objetivo pequeno, como implementar e testar uma função.
2. Leia a referência necessária para a entrega.
3. Implemente, execute e investigue o resultado.
4. Registre aprendizado e próximo passo no [diário](../templates/diario.md).
5. Revise o diff e faça um commit coerente.

Se o tempo for curto, reduza a entrega. Projetos pequenos executáveis e explicados ajudam a demonstrar evolução.
